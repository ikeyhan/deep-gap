# اتم ۳۱۳ — سایت + اپ اندروید

اکوسیستم کامل بازارگاه اتم ۳۱۳: **وب‌سایت فارسی (RTL)**، **پنل مدیریت**، و **اپ بومی اندروید** —
همه روی یک بک‌اند، یک پایگاه داده و یک مجموعه حساب کاربری.

```
                    ┌──────────────────────────────┐
   سایت (RTL) ────► │  Express + SQLite + JWT      │ ◄──── اپ اندروید
   پنل مدیریت ────► │  /api/*    (سایت و پنل)      │       (Kotlin/Compose)
                    │  /api/v1/* (اپ + همگام‌سازی) │
                    └──────────────────────────────┘
```

| پوشه | توضیح |
|---|---|
| `web/` | سایت، پنل مدیریت و بک‌اند (همان پروژهٔ قبلی، دست‌نخورده در رفتار) |
| `web/backend/` | سرور Node.js؛ `API-v1.md` مرجع کامل API اپ |
| `android/` | اپ بومی اندروید؛ `android/README.md` راهنمای ساخت و معماری |

## راه‌اندازی سریع

```bash
# ۱) بک‌اند + سایت
cd web/backend && npm install && npm start      # http://localhost:3000

# ۲) اپ اندروید (شبیه‌ساز به 10.0.2.2 وصل می‌شود)
cd android && echo "sdk.dir=/path/to/sdk" > local.properties
./gradlew assembleDebug

# ۳) نسخهٔ انتشار با دامنهٔ واقعی
./gradlew assembleRelease -Patom.apiBaseUrl=https://دامنهٔ-شما/
```

## تست‌ها

```bash
cd web/backend && npm test          # ۳۰ تست: API نسخهٔ ۱ و همگام‌سازی سایت↔اپ
cd android && ./gradlew testDebugUnitTest   # ۲۹ تست واحد اپ
```

## همگام‌سازی سایت و اپ

هر دو سمت روی همان جدول‌ها کار می‌کنند؛ این موارد تست خودکار دارند:

| اتفاق | نتیجه در سمت دیگر |
|---|---|
| ساخت حساب در سایت | ورود با همان حساب در اپ |
| ویرایش پروفایل در اپ | همان اطلاعات در «حساب من» سایت و پنل مدیریت |
| افزودن به علاقه‌مندی در هر سمت | نمایش در سمت دیگر (فهرست روی حساب ذخیره می‌شود) |
| ثبت سفارش در اپ | نمایش در داشبورد سایت، پنل مدیریت و «محصولات من» |
| تغییر وضعیت سفارش در پنل | اعلان در اپ + وضعیت تازه در هر دو سمت |
| پاسخ پشتیبانی در پنل | نمایش در حساب کاربر، در سایت و اپ |
| تغییر رمز در هر سمت | ابطال نشست‌های دیگر (سایت و اپ) |

## دسترس‌پذیری رنگ‌ها

کنتراست رنگ‌های هر دو پلتفرم با استاندارد **WCAG 2.1 AA** سنجیده شده است
(۴٫۵:۱ برای متن معمولی، ۳:۱ برای متن بزرگ و آیکون‌های معنادار):

- سبز دکمه‌ها از `#149B3E` به `#0E7A38` تغییر کرد — همان سبزِ ابتدای گرادیان برند؛
  متن سفید روی آن از ۳٫۶:۱ به ۵٫۴:۱ رسید. در تم تاریک اپ، برچسب دکمه تیره است (۶٫۷:۱).
- متن کم‌رنگ سایت، ستارهٔ امتیاز، نشان‌های روی تصویر محصول و متن روی چیپ‌های سبز نیز اصلاح شدند.
- `ContrastTest` در اپ این نسبت‌ها را برای همیشه تضمین می‌کند؛ برای سایت یک ممیزی مرورگری
  روی صفحهٔ رندرشده انجام شد.

## معماری امنیتی

- **جداسازی کامل پنل مدیریت**: حساب‌های `admin` / `editor` / `support` در API اپ با خطای
  `403 staff_not_allowed` رد می‌شوند — چه هنگام ورود، چه با توکن موجود. هیچ قابلیت مدیریتی در
  `/api/v1` وجود ندارد. مخفی‌کردن دکمه در رابط کاربری تکیه‌گاه امنیتی نیست؛ اجازه سمت سرور اعمال می‌شود.
- **قیمت‌ها فقط سمت سرور**: اپ و سایت فقط شناسهٔ محصول و تعداد می‌فرستند؛ جمع، تخفیف و هزینهٔ
  ارسال در `orders-service.js` محاسبه می‌شود (منطق مشترک هر دو سمت).
- **نشست**: توکن دسترسی کوتاه‌مدت + توکن نوسازی چرخشی با تشخیص سرقت. در اپ، نشست با کلید
  Android Keystore رمز می‌شود و از پشتیبان‌گیری خارج است.
- **بدون کلید در برنامه**: کلید هوش مصنوعی و اسرار فقط روی سرور می‌مانند؛ APK قابل مهندسی معکوس فرض شده است.
- **دسترسی به سفارش‌ها فقط بر اساس مالکیت حساب**: سفارش‌های مهمان با اثبات «کد سفارش + موبایل»
  به حساب متصل می‌شوند.

## پرداخت

درگاه پرداخت آنلاین هنوز به سایت متصل نیست؛ سفارش ثبت می‌شود و هماهنگی پرداخت و ارسال انجام
می‌شود. اپ همین وضعیت را از `/api/v1/config` می‌خواند (`commerce.onlinePayment=false`) و پیام
درست را نشان می‌دهد. هنگام افزودن درگاه، **تأیید پرداخت باید فقط روی سرور** (در callback درگاه و
با بررسی یکتایی شمارهٔ تراکنش) انجام شود — نه در اپ.

## اعلان‌ها

رویدادهای «ثبت سفارش»، «تغییر وضعیت»، «پاسخ پشتیبانی» و «پاسخ دفتر» در جدول `notifications`
ثبت می‌شوند. اپ آن‌ها را با همگام‌سازی دوره‌ای (WorkManager، هر ۳۰ دقیقه) می‌گیرد و جدول
`devices` برای افزودن پوش FCM در آینده آماده است؛ کلاس `PushMessageHandler` نقطهٔ اتصال است و
بقیهٔ اپ نیازی به تغییر ندارد.

## چک‌لیست انتشار

1. `web/backend/.env`: رمز مدیر را عوض کنید، `SEED_DEMO=0` بگذارید، `JWT_SECRET` را خالی
   بگذارید تا سرور کلید تصادفی بسازد.
2. سرور را پشت HTTPS و reverse proxy قرار دهید (اپ فقط HTTPS می‌پذیرد).
3. اپ را با `-Patom.apiBaseUrl=https://دامنه/` بسازید و با keystore خودتان امضا کنید
   (`android/keystore.properties`).
4. برای باز شدن لینک‌های سایت در اپ، `.well-known/assetlinks.json` را روی دامنه قرار دهید.
5. از `web/backend/data/` و `web/backend/uploads/` پشتیبان منظم بگیرید.
