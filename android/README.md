# اپلیکیشن اندروید اتم ۳۱۳

اپ بومی مشتریان، ساخته‌شده با **Kotlin + Jetpack Compose**، روی همان بک‌اند و همان
حساب‌های سایت (`/api/v1`). این یک WebView نیست: همهٔ صفحه‌ها بومی‌اند و فقط پیوندهای
بیرونی (تلگرام، تماس) به بیرون از اپ می‌روند.

## ساخت

```bash
cd android
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew assembleDebug                       # سرور محلی: http://10.0.2.2:3000
./gradlew assembleRelease -Patom.apiBaseUrl=https://دامنهٔ-شما/
./gradlew testDebugUnitTest                   # تست‌های واحد
```

آدرس سرور از `gradle.properties` خوانده می‌شود و با `-P` قابل جایگزینی است؛ هیچ آدرس یا
کلیدی در کد هاردکد نشده است.

### امضای نسخهٔ انتشار

فایل `android/keystore.properties` را بسازید (در گیت نیست):

```properties
storeFile=../release.keystore
storePassword=…
keyAlias=atom313
keyPassword=…
```

بدون این فایل، بیلد release با کلید debug امضا می‌شود (فقط برای آزمایش).

### پیوند دامنه (App Links)

برای اینکه لینک‌های محصول سایت در اپ باز شوند، فایل `.well-known/assetlinks.json` را با
اثرانگشت SHA-256 کلید انتشار روی دامنه قرار دهید.

## معماری

```
UI (Compose)  →  ViewModel  →  UseCase  →  Repository  →  Retrofit / Room / DataStore
```

| لایه | مسیر | نقش |
|---|---|---|
| طراحی | `core/designsystem` | توکن‌های رنگ/فونت/فاصله (برگرفته از CSS سایت) و کامپوننت‌های مشترک |
| شبکه | `core/network` | Retrofit، نگاشت خطا، افزودن توکن، نوسازی خودکار توکن، تشخیص آفلاین |
| امنیت | `core/security` | رمزگذاری نشست با Android Keystore (AES-256-GCM) روی DataStore |
| ذخیره | `core/database`, `core/datastore` | کش پاسخ‌ها (نمایش آفلاین)، سبد خرید، تنظیمات |
| داده | `data/repository`, `data/mapper` | منبع حقیقت هر حوزه و تبدیل DTO به مدل دامنه |
| دامنه | `domain/model`, `domain/usecase` | مدل‌ها و منطق کسب‌وکار مستقل از اندروید |
| رابط | `ui/*` | هر حوزه: ViewModel + صفحه‌ها |
| اعلان | `notifications` | انتشار اعلان، همگام‌سازی دوره‌ای، نقطهٔ اتصال آمادهٔ FCM |

### تصمیم‌های کلیدی

- **قیمت‌ها فقط سمت سرور**: اپ فقط `productId` و تعداد می‌فرستد؛ صورت‌حساب از `/cart/quote` می‌آید.
- **ثبت سفارش ایمن در برابر تکرار**: هدر `Idempotency-Key` مانع سفارش تکراری پس از قطع شبکه می‌شود.
- **نشست امن**: توکن‌ها رمزشده ذخیره می‌شوند، refresh چرخشی است و از پشتیبان‌گیری مستثناست.
- **بدون کلید در APK**: کلید هوش مصنوعی و اسرار فقط روی سرور می‌مانند.
- **کش با نمایش فوری**: صفحهٔ خانه و جزئیات ابتدا از کش نمایش داده می‌شوند و سپس تازه می‌شوند.
- **جداسازی پنل مدیریت**: حساب‌های `admin/editor/support` در API اپ رد می‌شوند (۴۰۳).
